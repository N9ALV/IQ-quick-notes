# Quick Notes review and release evidence — 8 September 2026

## Scope

This review covers the existing IQ Wealth adaptation of Roughdraft, not Hubble.
It preserves the one-local-Markdown-file model, Editing as the initial mode,
CriticMarkup, checklist saving and the finite agent review handoff. No account,
cloud note store, new IU entitlement or client authentication exception is added.

The source baseline was `464876d033a4a3c0d280474351b946cadefc422a`
(IQ Wealth package 0.1.2). Work and verification are native Windows, directly on
`main`, with no branches, pull requests or GitHub Actions/runs.

## Changes and reproduced defects

- Strict Host, Origin and peer checks close hostile-browser/network access to
  local APIs, preserving ordinary CLI and existing authenticated remote use.
- Sandboxed attachment responses prevent active HTML/SVG attachments from
  running with local app access. Real browser checks also covered PNG, SVG and
  PDF rendering.
- Real Edge testing also found that practice SVG Blob attachments could run
  on the app origin. Practice now accepts raster images/PDF and visibly rejects
  active formats without discarding the current draft.
- Failed explicit remote-session discovery now offers an error and retry,
  rather than falling back to browser storage and displaying a blank workspace.
- Current-draft copy/download replace stale last-saved copy behaviour. Failed
  clipboard access, loading and retry states are visible to the client.
- The client welcome page replaces developer marketing/setup. Practice is
  visibly temporary and isolated from local open-request events. Reading size
  persists without storing note content.
- A native per-user installer validates files, stages immutable versions,
  health-checks independently and atomically selects the active version.
  Friendly Start menu entries, stable launchers and verified rollback replace
  instructions that expected agents to invent those mechanisms.
- The actual Windows PowerShell 5.1 null-string behaviour at File.Replace was
  reproduced and corrected, rather than assuming another shell's semantics.
- Real-machine installation exposed a default-argument problem that explicit
  test parameters had masked. The package directory is now resolved in the
  installer body; regression checks invoke both the direct script and actual
  friendly installer without supplying a source-directory parameter.
- Compatible dependency patches and targeted same-major overrides address
  the advisories found by the initial audit. Build-only shadcn tooling is a
  development dependency. Runtime/dependency notices accompany the ZIP.
- pnpm 11's legacy hoisted deployment was proven to bypass the wanted lockfile.
  Packaging now uses the shared-lockfile deployment path and frozen production
  installation. Actual missing-snapshot and tampered-integrity fixtures must
  fail rather than resolving replacement dependency versions.
- Canonical Skill frontmatter was invalid YAML because of an unquoted colon;
  the existing YAML parser reproduced it. Updated guidance uses explicit
  verification/install/acceptance/rollback commands and preserves each
  client's personalised operating profile.

## Original client report and feedback

The six-page 12 August 2026 report was reviewed from its saved render. Several
reported 0.1.0 problems were already addressed by 0.1.1/0.1.2: finite replayable
watching, health reporting, a flat ZIP, managed agent help, note reload and
complete-path cross-folder opening. Those paths remain regression-tested.

The remaining installation ambiguity is addressed by a real installer, stable
friendly opener, Start menu discovery and deterministic updates. Registration
preserves VS Code and leaves the Markdown default to the user. Application
links are labelled separately from the Skill download. Client guidance names
one permanent IU page, not an unseen local file or a mandatory GitHub visit.

## Verification record

The final app check passed 427 tests (29 Markdown parser, 243 app, 155 server),
lint's error gate, selector checks and all builds. The final Edge browser
suite passed 30/30, and the separate smoke run passed 12/12. Nine existing
non-blocking lint warnings and the large frontend bundle warning remain.

`pnpm test:package:lock` passed four real deployment cases: valid lock,
missing lock, missing snapshot and tampered integrity. The resulting 69
registry dependencies plus local RFM match the reviewed versions/integrities
and contain no dependency symlinks. The full dependency audit reports zero
advisories at the time of verification; that is not a guarantee about future
advisories.

The exact 41,201,706-byte release ZIP passed packaged-runtime acceptance and
the full Windows lifecycle suite: legacy preservation, repeat installation,
12 unsafe-package rejections, failed-health preservation, separate-version
update and verified rollback. Captured agent/friendly commands return while
their server remains healthy under Windows PowerShell 5.1 and PowerShell 7.6.4.
Measured friendly launch took about six seconds, including full inventory
validation of about 2.6 seconds. This intentionally favours integrity checks
over minimal startup latency.

Independent review approved the server/UI corrections, the lockfile fix and
the final Windows/CLI source. Package identity is in the release notes.

The exact corrected ZIP was also installed into the actual per-user managed
location with the default Windows PowerShell installer command, including
registration and shortcuts. Version 0.2.0, the original 0.1.1 recovery pointer,
all three Start menu shortcut targets, quoted full-path association and
capability registration were checked. VS Code remained the Markdown default.
The installed friendly launcher opened and read two synthetic notes in
different folders; both were unchanged and the server reported healthy.
Only the acceptance test's isolated server was stopped afterwards.

Raw diagnostic logs and synthetic screenshots are
kept locally under `.context/review-2026-09-08/`, `.context/slog/` and
`.context/ui-state-screenshots/`; these are not client documents.

The browser harness uses installed Microsoft Edge when the Playwright browser
CDN is unavailable. CSS zoom checks are not a substitute for every browser's
native zoom menu. Test fixtures never establish that an ordinary IU member
download session has succeeded; that must be reported separately.
No interactive browser surface was available after the machine restart, so
ordinary signed-in IU delivery and native Open/Save picker interactions were
not certified. Automated Edge app tests, actual Windows registration/shortcut
metadata and exact-byte GitHub/R2 checks are separate evidence, not substitutes
for those two remaining interactive journeys.

## Canonical publication model

Current IU standards place live Markdown in Supabase `vault_documents` and
binary files in private R2 with `vault_assets` metadata. Retired GitHub content
trees, WorkDrive, Contabo and Baserow are not routine publishing targets.
Only the existing Quick Notes Skill is updated; no duplicate canonical article,
Skill ZIP or catalogue is created. IU access rules remain unchanged.
